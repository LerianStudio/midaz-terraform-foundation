# streaming-msk

Amazon MSK (Managed Streaming for Apache Kafka) as the AWS implementation of the Lerian
`STREAMING_*` contract.

The Lerian Helm charts publish and consume CloudEvents through `lib-streaming` over the Kafka
API. RedPanda is **never** packaged as a subchart — the broker is always external. On AWS that
broker is MSK, and this module is what a product root stack calls to get one.

| Product        | Streaming |
| -------------- | --------- |
| `br-sisbajud`  | Required  |
| `br-sfn`       | Required  |
| `midaz`        | Optional  |
| `plugin-fees`  | Optional  |

## Topics are NOT created here

Deliberately. Each chart creates the topics it owns from an ArgoCD **PreSync job running `rpk`**,
so the topic set is versioned and released together with the service that produces to it. This
module only provisions the cluster, its authentication and its network reachability.

For the same reason `auto.create.topics.enable` defaults to `false`: a typo in a producer must
fail loudly instead of silently creating a topic with the wrong partition count.

## One documented deviation from the module contract

MSK has no single hostname. It advertises a **comma separated list of bootstrap brokers**, so
`endpoint` is a `host:port` list rather than a host, and `port` is informational — it is already
embedded in every entry of that list. Consume `endpoint` (or `bootstrap_brokers_sasl_scram`,
which carries the same value for the default auth mode).

This is also why MSK was the first module to resolve its shared tier through a **data source**
instead of DNS: there was never an address a CNAME could point at. The rest of the repository
has since converged on the same pattern — every AWS datastore presents a certificate for its own
service domain, so an alias in front of it breaks TLS hostname verification. There is no private
zone, no CNAME and no `dns_name` output anywhere in this repository, and MSK is no longer the
exception it used to be.

In shared mode the cluster is resolved with `data "aws_msk_cluster"` on
`cluster_name = "shared-{environment}-msk"`, which returns the bootstrap broker lists directly.
Nothing is created and `security_group_id` is `null` — opening the shared cluster to a product is
the shared-resources/msk stack's job.

Note the two prefixes in `infra-base`: the foundation keeps `lerian-` (`lerian-{env}-vpc`,
`lerian-{env}-eks`), while the shared datastore tier uses `shared-`. The `shared-` prefix only
exists where a `dedicated` counterpart also exists; the VPC and the cluster have none.

A smaller deviation: the Secrets Manager path. **AWS requires the SCRAM secret name to
start with `AmazonMSK_`**, so the secret is `AmazonMSK_{product}-{environment}-msk` rather than the
usual `{product}-{environment}-{component}/password`.

`shared_secret_name` is the same escape hatch the other four modules expose — for when the shared
cluster's secret was created outside this Terraform. It defaults to
`AmazonMSK_shared-{environment}-msk`, and because the `AmazonMSK_` prefix is an AWS requirement
(`aws_msk_scram_secret_association` rejects anything else), a variable `validation` rejects an
override without it at plan time rather than letting the lookup resolve a secret MSK could never
have been associated with.

## Security defaults

- **At rest:** encrypted with a customer managed CMK created by this module (rotation enabled).
  Pass `encryption_at_rest_kms_key_arn` to bring your own.
- **In transit:** `TLS` between clients and brokers, and always TLS between brokers.
- **Authentication:** SASL/SCRAM. Credentials are generated by `random_password`, stored in
  Secrets Manager under a **second, separate CMK** — MSK rejects a SCRAM secret encrypted with the
  AWS managed `aws/secretsmanager` key, so the CMK is a hard requirement, not a hardening choice.
  The secret also carries a resource policy allowing `kafka.amazonaws.com` to read it.
- **Network:** a dedicated security group. Ingress is opened only on the ports the enabled
  authentication modes actually use — 9092 plaintext, 9094 TLS, 9096 SASL/SCRAM.

Five `precondition` checks fail the plan before anything is created if the combination is invalid:
no authentication mode enabled, SASL/SCRAM without TLS, mutual TLS without a CA ARN, a subnet
lookup that did not return exactly 2 or 3 subnets, or a broker count that is not a multiple of the
subnet count.

## Usage

Dedicated cluster for a product that requires streaming:

```hcl
module "streaming" {
  source = "../../_modules/streaming-msk"

  product     = "br-sisbajud"
  environment = var.environment

  allowed_security_group_ids = [module.eks.node_security_group_id]

  kafka_version          = "3.6.0"
  number_of_broker_nodes = 3
  broker_instance_type   = "kafka.t3.small"
  broker_ebs_volume_size = 100
}
```

Reusing the shared cluster from `infra-base`:

```hcl
module "streaming" {
  source = "../../_modules/streaming-msk"

  product     = "midaz"
  environment = var.environment
  mode        = "shared"
}
```

Helm values then read from the uniform outputs:

```hcl
streaming_brokers     = module.streaming.endpoint
streaming_secret_name = module.streaming.secret_name
```

## Inputs

### Contract

| Name                         | Type           | Default       | Description                                                                                        |
| ---------------------------- | -------------- | ------------- | -------------------------------------------------------------------------------------------------- |
| `product`                    | `string`       | —             | Product owning the cluster. `shared` for the shared one.                                            |
| `environment`                | `string`       | —             | One of `dev`, `stg`, `prd`. Validated.                                                              |
| `mode`                       | `string`       | `"dedicated"` | `dedicated` provisions a cluster, `shared` resolves `shared-{environment}-msk`.                      |
| `vpc_name`                   | `string`       | `""`          | `tag:Name` of the VPC. Empty derives `lerian-{environment}-vpc`.                                     |
| `subnet_tag_type`            | `string`       | `"database"`  | Value of the `Type` tag selecting broker subnets.                                                    |
| `subnet_ids`                 | `list(string)` | `[]`          | Overrides the subnet lookup. Use when the VPC tags more than 3 subnets.                              |
| `egress_cidr_blocks`         | `list(string)` | `["0.0.0.0/0"]` | Destinations the broker security group may reach. An empty list creates no egress rule.           |
| `shared_secret_name`         | `string`       | `""`          | `mode = "shared"` escape hatch: overrides the SCRAM secret name. Must start with `AmazonMSK_`. See above. |

### Ingress

**One rule, worded identically in all five Lerian datastore modules.**

- **Any** entry in `allowed_cidr_blocks` **or** `allowed_security_group_ids` →
  exactly those sources are allowed and **nothing else**. The VPC CIDR is never
  added on top. A caller who restricts, restricts.
- **Both** lists empty → fall back to the VPC CIDR when
  `allow_vpc_cidr_ingress` is `true`, or to **no ingress rule at all** when it is
  `false`.
- Rules are always scoped to a listener port, never to a whole protocol. Each
  resolved source gets one rule per enabled port: `9092` plaintext, `9094` TLS,
  `9096` SASL/SCRAM.
- `check "ingress_is_reachable"` warns at plan time whenever the resolved set
  comes out empty, so an unreachable cluster is never silent.

| Name | Type | Default | Description |
|---|---|---|---|
| `allowed_security_group_ids` | `list(string)` | `[]` | Security group IDs allowed on the enabled listener ports. Non-empty disables the VPC CIDR fallback. |
| `allowed_cidr_blocks` | `list(string)` | `[]` | CIDR blocks allowed on the enabled listener ports. Non-empty disables the VPC CIDR fallback. |
| `allow_vpc_cidr_ingress` | `bool` | `true` | **Fallback only.** VPC CIDR, applied only when both lists above are empty. |

> The fallback is **new** here. This module previously had none, so two empty
> lists produced zero ingress rules and a cluster no Kafka client could reach,
> with nothing in the plan output saying so. Both halves are fixed: the fallback
> keeps the cluster reachable, and the `check` block reports the still-empty case.

## Outputs

### Uniform datastore contract

| Name                | Description                                                                                     |
| ------------------- | ----------------------------------------------------------------------------------------------- |
| `mode`              | Echo of `var.mode`.                                                                              |
| `endpoint`          | Bootstrap broker list for the strongest enabled auth mode — the `STREAMING_BROKERS` Helm setting. A `host:port` list, not a host. |
| `port`              | `9096` SASL/SCRAM, `9094` TLS, `9092` plaintext. Already embedded in the broker list.             |
| `security_group_id` | Broker security group. `null` in shared mode.                                                    |
| `secret_arn`        | ARN of the SASL/SCRAM secret. `null` when SASL/SCRAM is disabled.                                 |
| `secret_name`       | Name of that secret, carrying the mandatory `AmazonMSK_` prefix.                                  |
| `identifier`        | MSK cluster name (the shared cluster's name in shared mode).                                      |

### Kafka specific

| Name                           | Description                                                     |
| ------------------------------ | --------------------------------------------------------------- |
| `bootstrap_brokers`            | Plaintext brokers, port 9092. Empty unless PLAINTEXT is allowed.  |
| `bootstrap_brokers_tls`        | TLS brokers, port 9094.                                          |
| `bootstrap_brokers_sasl_scram` | SASL/SCRAM brokers, port 9096.                                   |
| `zookeeper_connect_string`     | ZooKeeper connection string. Empty on KRaft-mode versions.        |
| `cluster_arn`                  | ARN of the cluster.                                              |
| `cluster_uuid`                 | Cluster UUID, for IAM policy resources.                          |
| `configuration_arn`            | ARN of the attached configuration.                               |
| `kms_key_arn`                  | CMK encrypting data at rest.                                     |
| `scram_kms_key_arn`            | CMK encrypting the SASL/SCRAM secret.                            |
| `log_group_arn`                | Broker log group. `null` when logging is disabled.                |
