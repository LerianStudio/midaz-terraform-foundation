# infra-base/vpc

Shared base VPC for one environment. Every Lerian product deployed into that
environment runs inside this VPC — it is created once per environment, not once
per product, which is why `product = "lerian"`.

Migrated from the pre-v2 `examples/aws/vpc` stack, which no longer exists — it
was removed in v2.

## What it provisions

| Resource | Name | Notes |
| --- | --- | --- |
| VPC | `lerian-{env}-vpc` | `terraform-aws-modules/vpc/aws ~> 5.0` (5.21.0 resolved) |
| Public subnets ×3 | `lerian-{env}-vpc-public-subnet-{az}` | `cidrsubnet(cidr, 8, 0..2)`, tag `Type=public` |
| Private subnets ×3 | `lerian-{env}-vpc-private-subnet-{az}` | `cidrsubnet(cidr, 8, 3..5)`, tag `Type=private` |
| Database subnets ×3 | `lerian-{env}-vpc-database-subnet-{az}` | `cidrsubnet(cidr, 8, 6..8)`, tag `Type=database` |
| NAT Gateways | managed by the module | 1 shared in dev, 1 per AZ in stg/prd |
| Flow logs | log group `/aws/vpc-flow-log/lerian-{env}-vpc` | IAM role and policy `lerian-{env}-vpc-flow-logs` |
| Interface VPC endpoints | `lerian-{env}-vpc-endpoint-{service}` | `rds`, `secretsmanager`, `elasticache` by default |
| Endpoint security group | `lerian-{env}-vpc-endpoints` | 443 from the VPC CIDR, no egress |
| S3 gateway endpoint | `lerian-{env}-vpc-endpoint-s3` | on the private + database route tables |
| Database network ACL | `lerian-{env}-vpc-database-nacl` | allows the private and database subnets only |
| Default security group | `lerian-{env}-vpc-default` | emptied (no ingress, no egress) |

Everything is tagged from `_modules/naming`: `Product`, `Environment`,
`ManagedBy`, `Repository`, plus whatever `extra_tags` carries.

### Subnet tags are a contract

- `Type = public | private | database` — every datastore module in
  `examples/aws/_modules` resolves its subnet group with
  `data "aws_subnets"` filtered on `tags = { Type = "database" }`. Renaming or
  dropping this tag breaks every datastore stack.
- `kubernetes.io/role/elb = 1` on public, `kubernetes.io/role/internal-elb = 1`
  on private — subnet auto-discovery for the AWS Load Balancer Controller.
- `kubernetes.io/cluster/lerian-{env}-eks = shared` on public and private.

## The cross-stack problem this stack solves

`cluster_name` used to be a literal typed into the tfvars (`midaz-eks`). The tag
it produces is what an EKS cluster uses to find its own subnets, but the cluster
is created by a **different** stack, and nothing at apply time cross-checks the
two strings. A mismatch fails silently and late: the cluster comes up fine, and
load balancer provisioning later fails with "no subnets found".

So the name is now **derived**:

```hcl
cluster_name = var.cluster_name != "" ? var.cluster_name : "${module.naming.prefix}-eks"
```

With the mandated `product = "lerian"` this resolves to `lerian-{env}-eks`, which
is exactly what `infra-base/eks` derives for itself from the same naming module
with `component = "eks"`. **Both stacks must agree on this string.** The derived
value is exported as the `cluster_name` output so the agreement is verifiable
with `terraform output` instead of by eye.

`var.cluster_name` remains as an escape hatch for pointing these subnets at a
cluster that was not created by `infra-base/eks`. Overriding it with anything
that is not the real cluster name reintroduces the exact failure above.

## Deploy order

```
bootstrap (once per env)  ->  infra-base/vpc  ->  infra-base/eks  ->  [products/shared-resources/* se optar]  ->  produtos
```

`vpc` is the first stack after the state bootstrap: every datastore module
resolves both the VPC and the `Type=database` subnets by `tag:Name` and by
`tag:Type`, and `infra-base/eks` resolves the VPC and the `Type=private` subnets
the same way.

## Init and apply

```bash
cd examples/aws/infra-base/vpc

terraform init \
  -backend-config=../../backend/dev.hcl \
  -backend-config="key=aws/infra-base/vpc/terraform.tfstate"

cp envs/dev.tfvars-example envs/dev.tfvars   # *.tfvars is gitignored
terraform plan  -var-file=envs/dev.tfvars
terraform apply -var-file=envs/dev.tfvars
```

Switching environments in the same checkout requires `-reconfigure`. The state
**key stays the same** — segregation comes from the bucket, one per environment,
created by `examples/aws/bootstrap`:

```bash
terraform init -reconfigure \
  -backend-config=../../backend/stg.hcl \
  -backend-config="key=aws/infra-base/vpc/terraform.tfstate"
```

`backend.tf` is deliberately empty — see the comment in it. `../../backend/{env}.hcl`
is generated by `examples/aws/bootstrap` and is gitignored (it contains the AWS
account id).

## Outputs consumed downstream

| Output | Consumed by | How |
| --- | --- | --- |
| `vpc_name` | every datastore module, `products/shared-resources`, `infra-base/eks` | as `vpc_name`, resolved via `data "aws_vpc"` on `tag:Name` |
| `cluster_name` | `infra-base/eks` | must equal the cluster name that stack creates |
| `vpc_id` | `infra-base/eks` | direct |
| `vpc_cidr_block` | datastore modules | ingress CIDR for security group rules |
| `database_subnet_ids` | datastore modules | normally resolved by `tag:Type=database` instead |
| `private_subnet_ids` | `infra-base/eks` | node groups and interface endpoints |
| `public_subnet_ids` | `infra-base/eks` | internet-facing load balancers |
| `azs` | `infra-base/eks`, datastore modules | AZ ordering of the subnet lists |
| `nat_public_ips` | partner and BACEN allowlists | the egress addresses of this environment |
| `private_route_table_ids`, `database_route_table_ids` | further gateway endpoints, transit gateway | direct |
| `vpc_endpoint_ids`, `vpc_endpoint_security_group_id` | audit and troubleshooting | direct |

## Decisions

### No `default_tags` on the provider

Every resource tags itself from `module.naming.tags`, so `default_tags` would
only duplicate them, and invisibly: injected tags do not appear in the resource
bodies, `terraform plan` attributes them to the provider, and the tag set would
then depend on provider configuration rather than on the naming contract that
every cross-stack `tag:Name` lookup resolves against. It is also a known source
of perpetual diffs on `terraform-aws-modules` resources that compute their own
`Name` tag. `var.extra_tags` is the extension point instead — it flows through
`module.naming` into every resource, visibly and in state.

### S3 gateway endpoint on by default

Gateway endpoints have no hourly charge and no data processing charge. Without
one, S3 traffic from the private subnets leaves through the NAT Gateway, where
the same bytes are billed. Now that Lerian products read and write S3 directly
(reporter, fetcher, bc-correios), this is a straight cost reduction with no
downside — `enable_s3_gateway_endpoint = true`.

### `kms` and `sts` interface endpoints: available, not default

Interface endpoints bill roughly USD 0.01/hour **per AZ** plus data processing —
about USD 22/month per service across three AZs. Both services are already
reachable through the NAT Gateway this stack provisions, so an endpoint buys
private-only routing and lower NAT data charges, not new capability:

- `sts` — IRSA token exchange, once per pod start. Negligible traffic; the
  endpoint pays for itself only in a VPC with no NAT at all.
- `kms` — called on every Secrets Manager decrypt and on RDS/DocumentDB storage
  key operations. Worth enabling in prd when NAT data processing shows up in the
  bill, and mandatory if the private subnets ever lose their NAT route.

They are therefore controlled by `interface_endpoint_services`, which defaults to
the three data-path services and is extended to five in `envs/prd.tfvars-example`.

### Corrections applied while migrating

| Was | Now | Why |
| --- | --- | --- |
| `var.name`, default `midaz-vpc` | `product` + `environment` via `_modules/naming` | dev/stg/prd in one account cannot collide |
| `cluster_name = "midaz-eks"` typed in tfvars | derived `{product}-{env}-eks`, exported as an output | a typo silently breaks EKS subnet discovery |
| Endpoint SG allowed 5432/6379 from the VPC | endpoint SG allows 443, no egress | interface endpoints terminate HTTPS; database ports on an endpoint ENI do nothing. Datastore security groups belong to the datastore modules |
| Endpoint SG created by the upstream submodule | created here | the submodule applies `create_before_destroy` to it, which deadlocks against the exact (non-prefixed) name the anti-collision rule requires |
| Flow log IAM role named `vpc-flow-log-role-*` | `lerian-{env}-vpc-flow-logs` | IAM role names are account-global; an auditable name beats a random suffix |
| Flow log retention not configurable | `flow_logs_retention_days` per env | flow logs are the second largest cost in this stack after NAT |
| Database NACL allowed private subnets only | allows private **and** database subnets | **latent bug**: network ACLs are evaluated on database-to-database traffic across AZs, which is the path used by RDS Multi-AZ replication, DocumentDB replica sets and ElastiCache replication. The old rules left every multi-AZ datastore unable to replicate |
| NACL CIDRs re-derived by hand (`cidrsubnet(cidr, 8, 3)` ×6) | generated from the same `locals` as the subnets | one copy of the arithmetic cannot drift from the other |
| `kubernetes.io/cluster/... = "owned"` | `= "shared"` | the subnets are owned by this stack, never by the cluster; `shared` is the AWS-documented value and it allows a second cluster (blue/green control-plane upgrade) to reuse them |
| Default security group left wide open | `manage_default_security_group`, ingress and egress emptied | removes the implicit allow-all any ENI created without an explicit SG would land on |
| Subnet count assumed to be 3 with no check | `validation` on `availability_zones` and on `vpc_cidr` | the `k`/`k+3`/`k+6` layout only holds for exactly 3 AZs and a prefix of /20 or wider |
| `additional_tags` + `resource_tags` maps | `extra_tags` into `_modules/naming` | one tagging path, one source of truth |

## Validation

```bash
terraform fmt -recursive . && terraform fmt -check -recursive .
terraform init -backend=false -input=false
terraform validate
```

`terraform validate` reports one warning, from inside
`.terraform/modules/vpc/vpc-flow-logs.tf`: the upstream module still reads
`data.aws_region.current.name`, deprecated in the AWS provider. It is upstream
code, not this stack, and it clears on the next VPC module release.
