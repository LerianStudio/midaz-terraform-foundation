# Security Policy

## Reporting a vulnerability

**Do not open a public GitHub issue for a security vulnerability.**

Email **security@lerian.studio** with:

- what the vulnerability allows an attacker to do
- the steps to reproduce it
- the affected git tag of the templates

We acknowledge within two business days.

## Supported versions

| Version | Supported |
| ------- | --------- |
| 1.x     | yes       |

The CLI that drives these templates lives in `LerianStudio/lerian-infra-cli` and has
its own SECURITY.md; report CLI issues there.

## What this repository does and does not hold

The templates provision AWS infrastructure, so the security boundary is worth stating
plainly.

**Never in this repository, by design:**

- **AWS account ids.** `examples/aws/environments.conf` and every
  `examples/aws/backend/<env>.hcl` are gitignored, because the state bucket name
  embeds the account id. The committed files are `*.example`.
- **Credentials of any kind.** Passwords and auth tokens are generated by Terraform
  into AWS Secrets Manager and never leave it. The `helm_values` outputs carry
  `secret_arn` and `secret_name` — references, never values — so the whole Helm
  handoff document can be printed, logged or pasted without leaking anything.
- **Terraform state.** `*.tfstate` and `terraform.tfstate.d/` are gitignored. State
  can contain values read back from resources.

**Saved Terraform plans** can embed values read from state. Do not archive or attach
them.
